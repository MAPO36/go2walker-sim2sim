4.0 先说边界
--------------------------------------------------------------------------------
这一部分只给方案、代码片段和细节，**本次没有修改任何训练代码**。
你确认方案后，再按 4.3 的步骤实施。

目标：当速度指令为 0 时，机器人应该站定；现在它会以约 2.6 cm/s（MuJoCo）
或 1.0 cm/s（Isaac Gym）慢慢往前蹭。希望通过奖励函数把这点残余速度压下去。

重要前提：
  - 这需要重新训练（奖励只在训练时起作用）。
  - 不需要改观测，所以 MuJoCo yaml 的 num_obs / observation_layout 不用动；
    但训练完要重新导出 policy_1.pt，MuJoCo 会自动读同一个路径。
  - 不需要改 commands.ranges（±1.0 是训练契约）。
  - 不需要改 PD、动作缩放、网络结构。


4.1 为什么现在的奖励压不住这点漂移
--------------------------------------------------------------------------------
(1) tracking_lin_vel 在 0 附近太“平”
    公式：exp(-v² / 0.25)
    在 v = 0.026 m/s 时：exp(-0.000676/0.25) ≈ 0.9973。
    也就是说，从“完美站定”到“2.6 cm/s 漂移”，只损失 0.27% 的跟踪奖励。
    它的梯度 d/dv = -(2v/0.25)exp(...) ≈ -0.21（每 m/s），
    在 v 接近 0 时趋近于 0。策略没有动力去压最后这一点。

(2) 0 指令在训练里不多
    vx、vy 各自 U(-1,1)，长度小于 0.2 时清零。
    清零的概率 = 半径 0.2 的圆面积 / 边长 2 的正方形面积
                = π×0.04 / 4 ≈ 3.14%。
    每个 episode 20 秒、每 10 秒重采样一次，所以大约 3.1% 的时间是 0 线速度指令。
    再加上 heading_command=True 时 wz 通常不为 0，
    “完全站定”的样本更少。

(3) 所以需要一个“在 0 指令时专门生效”的惩罚项
    关键：门控（gate）。只在指令为 0 时惩罚，不能影响正常行走。


4.2 方案设计：
--------------------------------------------------------------------------------
1 指令时的机身线速度惩罚
  门控：norm(commands[:, :2]) < 0.2
  惩罚：norm(base_lin_vel[:, :2])   （用一次范数，不用平方）
  权重：建议 -2.0 起步，可在 -1.0 ~ -5.0 之间调
  优点：
    - 不需要新状态，代码最少；
    - 线性项在 v=0 处梯度不为 0，能真正把残余速度压下去；
    - 只影响 0 指令样本，正常行走完全不受影响。
  效果估算：
    - 在 0.026 m/s 时，惩罚 = -2.0 × 0.026 = -0.052/秒；
      而 tracking 的损失只有 -0.0027/秒，所以惩罚主导；
    - 在 0.1 m/s 时，惩罚 = -0.2/秒；
    - 在 0.5 m/s 时，惩罚 = -1.0/秒，已经和 tracking 满分同量级。
  注意：
    - 不要用 v²，因为平方项在 0 附近梯度也趋近 0；
    - 不要惩罚全部速度（包括 wz），否则会干扰原地转向；
    - 训练时有推机器人（每 15 秒一次），被推的瞬间速度会变大，
      惩罚会短暂变大；这是可以接受的，权重不要太大即可。


2（不一定需要加）：0 指令时的动作/关节速度惩罚
  门控：norm(commands[:, :2]) < 0.2 且 |commands[:,2]| < 0.1
  惩罚 1：sum(dof_vel²)       权重 -5e-3 ~ -2e-2
  惩罚 2：sum(actions²)       权重 -0.02 ~ -0.1
  优点：直接对应“动作”，能让狗站得更“死”，减少原地小碎步。
  风险：
    - 站定也需要微小的关节运动来保持平衡，惩罚太大会让它僵住、被推倒；
    - 与 alive/orientation 可能打架，所以权重必须小。
  建议：先不加；如果 1 之后狗还在原地小碎步，再加 2。


推荐组合（按风险从低到高）：
  第一轮：只加 A，权重 -2.0。
  第二轮：如果原地小碎步，加 C（dof_vel -5e-3）。

不建议的做法：
  - 把 tracking_lin_vel 的 sigma 改小来“放大”近零误差：
    会让所有速度的跟踪都变难，训练不稳定。
  - 在 0 指令时惩罚所有关节位置偏离默认角：
    站立时腿本来就不是默认角，会打架；基类的 _reward_stand_still
    是惩罚 dof_pos 偏离默认角，Go2 没有启用，也不建议直接开大。
  - 直接加大动作/力矩惩罚：会影响正常行走。

第 1 步：在 go2_env.py 里加奖励函数
  在 GO2Robot 类里追加（放在 _reward_hip_pos 后面即可）：

    def _reward_zero_cmd_lin_vel(self):
        """0 线速度指令时，惩罚机身的水平速度。

        用一次范数而不是平方：平方项在 v→0 时梯度也→0，
        压不住最后那 1~3 cm/s 的残余漂移；一次范数在 0 附近梯度是常数。
        门控用 0.2，和 _resample_commands() 里的清零阈值一致。
        """
        is_zero_cmd = (torch.norm(self.commands[:, :2], dim=1) < 0.2).float()
        return torch.norm(self.base_lin_vel[:, :2], dim=1) * is_zero_cmd

  可选（方案 2，先别加，等需要时再加）：

    def _reward_zero_cmd_dof_vel(self):
        """0 指令（线速度和偏航都接近 0）时，惩罚关节速度。"""
        is_zero_cmd = (
            (torch.norm(self.commands[:, :2], dim=1) < 0.2)
            & (torch.abs(self.commands[:, 2]) < 0.1)
        ).float()
        return torch.sum(torch.square(self.dof_vel), dim=1) * is_zero_cmd

    def _reward_zero_cmd_action(self):
        """0 指令时，惩罚动作幅值，让策略更接近默认站姿。"""
        is_zero_cmd = (
            (torch.norm(self.commands[:, :2], dim=1) < 0.2)
            & (torch.abs(self.commands[:, 2]) < 0.1)
        ).float()
        return torch.sum(torch.square(self.actions), dim=1) * is_zero_cmd
